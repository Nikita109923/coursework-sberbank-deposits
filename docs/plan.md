# План курсовой работы «Сбербанк. Сведения о вкладчиках банка»

**Тема:** Сбербанк. Сведения о вкладчиках банка: номер лицевого счета, категория вклада, паспортные данные, текущая сумма вклада, дата последней операции. Операции приема и выдачи любой суммы, автоматическое начисление процентов.

**Дисциплина:** Технологии программирования
**Подход:** объектно-ориентированный, итеративная разработка с публикацией кода на GitHub
**Стек:** C#, .NET 9, WPF, паттерн MVVM, хранение данных в JSON-файлах

---

## 1. Бизнес-требования

Учет вкладов в отделении банка часто ведется вручную или в разрозненных таблицах. Из-за этого операционист тратит время на поиск счета вкладчика, ошибается при пересчете остатка и начислении процентов, а руководство не может быстро получить сводку по вкладам.

Система предназначена для автоматизации учета вкладчиков банка и операций по их вкладам. Цель — сократить время обслуживания клиента, исключить ошибки ручного расчета процентов и остатков и хранить полную историю операций по каждому счету.

Ожидаемый эффект:
- поиск вкладчика по номеру счета, ФИО или паспорту за секунды;
- остаток и проценты рассчитываются автоматически, без ручного пересчета;
- по каждому счету есть журнал операций, по которому можно восстановить историю остатка.

## 2. Видение проекта

### 2.1. Пользователи (роли)

| Роль | Цель работы в системе |
|---|---|
| **Операционист** | Ведет карточки вкладчиков, открывает и закрывает вклады, проводит прием и выдачу денег |
| **Администратор** | Ведет справочник категорий вкладов (процентные ставки, условия), просматривает журнал действий, запускает начисление процентов |

> Разделение ролей с входом по логину и паролю — дополнительная функциональность (спринт 5). В MVP приложение работает от имени одного пользователя со всеми правами.

### 2.2. Функции по ролям

**Операционист:**
- открыть вклад: ввести паспортные данные вкладчика, выбрать категорию вклада, внести первоначальную сумму;
- просмотреть список вкладов;
- найти вклад по номеру лицевого счета, ФИО или номеру паспорта;
- отфильтровать вклады по категории;
- отсортировать список по сумме вклада, дате последней операции или ФИО;
- изменить паспортные данные вкладчика;
- принять на вклад любую сумму;
- выдать с вклада любую сумму, не превышающую остаток;
- просмотреть историю операций по счету;
- закрыть вклад, выдав весь остаток;
- выгрузить список вкладов в CSV.

**Администратор:**
- изменить параметры категории вклада: годовую ставку, минимальную сумму открытия;
- прекратить или возобновить прием новых вкладов по категории (открытые вклады продолжают обслуживаться);
- запустить начисление процентов вручную;
- просмотреть журнал действий (лог).

### 2.3. Границы проекта

**В проект входит:**
- настольное приложение с графическим интерфейсом WPF;
- хранение данных в JSON-файлах;
- одна валюта (в интерфейсе — BYN);
- начисление процентов по ставке категории вклада;
- журнал операций и журнал действий пользователя.

**В проект не входит:**
- СУБД и сетевой или многопользовательский одновременный доступ;
- веб-версия и мобильное приложение;
- мультивалютные вклады и конвертация;
- интеграция с реальными банковскими системами и платежами;
- кредиты, карты, переводы между счетами.

## 3. Модель данных

### 3.1. Вкладчик (`Depositor`): паспортные данные
| Поле | Тип | Правило проверки |
|---|---|---|
| Фамилия, имя, отчество | string | обязательны (кроме отчества); только буквы, пробел и дефис |
| Дата рождения | DateOnly | не в будущем, возраст не меньше 14 лет |
| Серия и номер паспорта | string | 2 заглавные буквы + 7 цифр (например, `MP1234567`) |
| Идентификационный (личный) номер | string | 14 символов, латиница и цифры |
| Кем выдан | string | обязательно |
| Дата выдачи | DateOnly | не в будущем, не раньше даты рождения |
| Адрес регистрации | string | необязательно |

### 3.2. Категория вклада (`DepositType` и `DepositCategory`)
Набор категорий фиксирован перечислением `DepositType`; русское название задано атрибутом `[Description]`. Параметры каждой категории хранятся в записи `DepositCategory` и настраиваются в справочнике.

| Поле | Тип | Пример |
|---|---|---|
| Категория | enum `DepositType` | `OnDemand` («До востребования»), `Savings` («Накопительный»), `Pension` («Пенсионный») |
| Годовая ставка, % | decimal | 0,5 / 9,0 / 10,5 |
| Минимальная сумма открытия | decimal | 0 / 100 / 50 |
| Прием новых вкладов | bool | да / нет |

Добавить новую категорию — значит добавить значение в `DepositType`. Это изменение кода, зато категория не может оказаться опечаткой или «висячей» ссылкой. Параметры новой категории берутся из `DefaultData` при следующем запуске.

### 3.3. Вклад или лицевой счет (`Account`)
| Поле | Тип | Примечание |
|---|---|---|
| Номер лицевого счета | string | 20 цифр, генерируется автоматически и уникален |
| Вкладчик | Depositor | композиция |
| Категория | enum `DepositType` | параметры — в `DepositCategory` |
| Текущая сумма вклада | decimal | только для чтения снаружи, меняется через операции |
| Начисленные, но не выплаченные проценты | decimal | накапливаются ежедневно |
| Дата открытия | DateOnly | |
| Дата последней операции | DateTime | обновляется при приеме, выдаче и капитализации процентов |
| Дата последнего начисления | DateOnly | служебное поле для расчета процентов |
| Статус | enum `AccountStatus` | `Open` («Открыт»), `Closed` («Закрыт») |

### 3.4. Операция (`Operation`)
| Поле | Тип |
|---|---|
| Идентификатор | Guid |
| Номер счета | string |
| Тип | enum: `Open`, `Deposit` (прием), `Withdrawal` (выдача), `Interest` (начисление процентов), `Close` |
| Сумма | decimal |
| Остаток после операции | decimal |
| Дата и время | DateTime |

Все суммы хранятся в `decimal` и округляются до копеек (2 знака). Тип `double` для денег не используется.

## 4. Алгоритм автоматического начисления процентов

1. Проценты считаются **ежедневно** на фактический остаток по формуле:
   `проценты за период = остаток × ставка / 100 × число_дней / число_дней_в_году` (365 или 366).
2. Перед **любой** операцией со счетом (прием, выдача, закрытие) сервис сначала начисляет проценты с даты последнего начисления по текущую дату. Поэтому на каждом отрезке между начислениями остаток постоянен, и расчет точный.
3. Начисленные проценты накапливаются в поле «начисленные проценты» и **капитализируются** (прибавляются к сумме вклада отдельной операцией `Interest`) в последний день каждого месяца и при закрытии вклада.
4. **Автоматический запуск:** при старте приложения сервис проходит по всем открытым счетам и досчитывает проценты за пропущенные дни и месяцы, в том числе если программа долго не запускалась. Администратор может запустить расчет и вручную.
5. Текущая дата берется через интерфейс `IClock`. Это позволяет в тестах «перемотать» время и проверить начисление за месяц или год.

### 6.3. Примененные паттерны

| Паттерн | Где | Зачем |
|---|---|---|
| MVVM | `ViewModels`, `Views` | Окна без логики, модели представления тестируются без интерфейса |
| Команда (Command) | `[RelayCommand]` | Действия пользователя и их доступность (`CanExecute`) |
| Внедрение зависимостей, корень композиции | `App.ConfigureServices` | Все зависимости собираются в одном месте |
| Репозиторий | `IRepository<T>`, `JsonRepository<T>` | Способ хранения скрыт от логики; в тестах — хранилище в памяти |
| Единица работы (Unit of Work) | `BankContext` | Изменения коллекций сохраняются одним вызовом |
| Корень агрегата | `Account` | Сумма вклада меняется только через сервис, с записью в журнал |
| Шаблонный метод | `AccountService.Execute` | Общий порядок любой операции: найти счет → начислить проценты → действие → журнал → сохранение |
| Фабрика | `IViewModelFactory` | Главная модель не знает зависимостей диалогов |
| Реестр представлений (View Locator) | `DialogService` | Сопоставление «модель представления → окно» |
| Конвертер значений | `EnumDescriptionConverter` | Перечисления показываются по-русски без строк в моделях |
| Объект-значение | записи `Depositor`, `DepositCategory`, `Operation` | Неизменяемость и сравнение по значению |

### 6.4. Библиотеки и инструменты
- `CommunityToolkit.Mvvm` — `ObservableObject` и `RelayCommand`, чтобы не писать шаблонный код MVVM;
- `Microsoft.Extensions.DependencyInjection` — контейнер внедрения зависимостей;
- `System.Text.Json` — сериализация (встроена в .NET);
- собственный `FileAuditLog` — журнал действий в текстовом файле, без внешних зависимостей;
- `xUnit` — модульные тесты;
- анализаторы .NET (`AnalysisLevel=latest-recommended`), `.editorconfig`, `dotnet format`; предупреждения считаются ошибками.

## 9. Принятые решения

- Валюта — белорусский рубль (BYN).
- Срочные вклады не реализуются: по теме допускается выдача любой суммы, поэтому ни одна категория не ограничивает снятие.
- Программа работает от имени одного пользователя; разграничение ролей — направление дальнейшего развития.
